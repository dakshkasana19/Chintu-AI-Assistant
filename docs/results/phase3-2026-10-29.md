# Phase 3 Results — Command ASR (2026-10-29)

## Implemented

- Added `chintu/asr.py` for local faster-whisper command transcription using CPU/int8, defaulting to the already cached `base` model.
- Added a bounded command-segment queue and ASR worker thread. Only new VAD-delimited utterances after wake confirmation are queued; the utterance that triggered wake remains wake-only.
- Reused the loaded `base` Whisper model for wake confirmation and command ASR. Other supported model sizes can be configured and explicitly prepared.
- Kept raw transcript and normalized command separate. Normalization removes leading “Chintu” and request fillers and converts cardinal number words through 99 to digits.
- Rejects invalid/silent audio and likely hallucinations using no-speech probability, average log probability, and compression ratio.
- Added `scripts/eval_asr.py` to compute raw and normalized-command WER over paired, one-utterance 16 kHz mono PCM16 WAV/reference files.
- Updated configuration, model preparation CLI, doctor output, README, and development logs. Phase 2's detector behavior and the approved `#FFE550` UI were preserved.

## Manual test still required

1. Start the assistant and confirm its overlay remains hidden while it is in standby.
2. Say “Chintu” and wait for wake confirmation.
3. Then speak a separate command, such as “What is today's date?”
4. Verify that only the second utterance is sent to ASR and inspect the raw and normalized transcript values.
5. Repeat with silence/background noise and ordinary non-command speech.

The approved overlay is intentionally text-free. The raw and normalized transcript values are retained through the runtime result and existing UI bridge signals, but are not rendered as text on the overlay. No live command WER/accuracy has been established. The evaluator command is documented in the README; keep any report containing personal transcripts local.
